# Release v1.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从当前 `main`(ebc4b08)切出 Kobold v1.3.0,打包并发布 GitHub Release。

**Architecture:** 纯发布变更(不动应用代码):提升单一版本真源(`Kobold.csproj`),把 `CHANGELOG.md` 的 `Unreleased` 转为 `## v1.3.0 (2026-09-28)`;README(英/中)补齐 v1.2.0 之后的四项用户可感知变化;全量自检后由 `tools/package.ps1` 打包;提交 `chore(release): v1.3.0`(带 `[ci]`),打轻量标签 `v1.3.0`,推送后用 `tools/release-notes.ps1` 生成的正文创建 GitHub Release。

**Tech Stack:** .NET SDK 8 构建 net48 WPF;PowerShell 5.1 工具链;GitHub CLI(已登录 zzrqq-worklux,repo 权限)。

**Spec:** README「构建与测试 / Update」发布小节;`CHANGELOG.md` 头部约定(Unreleased 发布时原样成为版本小节);`tools/release-notes.ps1`(正文必须来自 CHANGELOG,缺小节硬报错);先例提交 `ddfb763`(发布提交 = 版本号 + README 更新 + 打包 zip 入库)。

## Global Constraints

- 版本单一真源是 `Kobold.csproj` 的 `<Version>`;`package.ps1` / `release-notes.ps1` 默认读取它。
- Release 正文只能由 `CHANGELOG.md` 的 `## v1.3.0` 小节生成,不手写。
- 本发布不改任何应用代码;若某步需要改代码,停下来重新计划。
- 打包 zip 随发布提交入库(`.gitignore` 有 `!Releases/`;历次发布均如此)。
- `[ci]` 标记放在发布提交(HEAD)的提交信息里,触发 GitHub Checks。
- 标签沿用 v1.1.0 / v1.2.0 的轻量标签风格。
- 本机正运行着**已安装副本**(`%LocalAppData%\Programs\Kobold\Kobold.exe`);构建/打包不触碰它,仅可选的演练任务会。
